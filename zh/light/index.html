实验性 · Relax 与 Rust 项目及 Rust 基金会无关，也未获其认可。它是由 AI 生成的 Rust 语言重新实现，旨在降低大语言模型处理 Rust 代码时的延迟，仅应视为实验性开发工具：运行时可能存在任意数量的缺陷，也不会自动继承 Rust 的安全保证。Relax 用于开发迭代。任何发布版本请使用 Rust 本身构建（cargo build --release）。目前它主要在 Makepad 自身的编辑-运行迭代中测试过，在其他项目上测试还很少；在别处使用时可能遇到问题，欢迎反馈。

本页的文字由 JavaScript 填充。以下是同一内容的纯 HTML 版，供不运行 JavaScript 的读者使用；英文原文见 README 和 纯 HTML 版。

Rust，告别等待。

rustc：先构建，再运行。Relax：边构建，边运行。

  • 1.15 s 同一个游戏再次运行：什么都不用重新编译

JIT 的代价。

  • 优化后的代码更慢：耗时是针对本机 CPU 的 --release 的 1.14–1.26 倍，密集数值循环上是 2.3 倍（还不做向量化）。详情
  • 占用更多内存：编译器、它的缓存和所有已发布的代码都与你的程序同处一个进程；JIT 代码只增不减。见 relax inspect <pid> memory。
  • 检查还不比 cargo 快：在大型包上，冷启动的 relax check 比 cargo check 更慢、占用更多内存，一次编辑也可能重新检查超出需要的部分。我们正在改进。
  • 有些改动需要重启：函数体的改动实时打补丁。结构体布局、导入、trait 或 impl 头、宏的改动要等 relax inspect <pid> session relaunch。
  • 借用检查在后台：每个函数先做类型检查再运行；借用检查与程序并行，除非加上 --check-first。
  • 已知缺口：还不是每个 crate 都能跑：KNOWN_GAPS.md 逐项列出，每项附复现。
  • 不能替代发布构建：Relax 用于编辑—运行循环。发布时请用 cargo build --release 构建的产物。

JIT 带给你的。

relax run 会打印 relax-remote: pid <pid>。下面除 run 和 test 外的命令都发给 relax inspect <pid>，由运行中的程序回答。

热补丁，状态保留保存文件，改过的函数就被重新检查、重新编译，并热替换进运行中的程序。调用到编译不过的代码时，调用会等你修好。relax run <package>
保存即测测试保持预热，只重跑进入过你所改函数的那些。relax test --live <package>
panic 时暂停panic 的线程停住，栈保持完整（终端里 10 分钟，无人值守 2 s）。读它的局部变量、在它的栈帧里求值 Rust，然后让它展开，或重跑一个 restartable 函数。panics、locals panic=P1、eval <expr>、resume P1 panic
断点，不用调试器命中时线程停在调用处，栈保持完整。break <file>:<line>、locals break=K1、continue
卡死，讲清原因死锁、阻塞、忙碌还是空闲：结论、等待链和相关线程的栈。why-hung
性能剖析对 JIT 帧和原生帧采样：每个线程的 CPU、最热的函数及其最热的一行、带层级的调用树、火焰图用的栈。prof s=3、prof view=tree、why-slow
飞行记录器始终开启，内存有上限：最近几分钟的线程、等待、编译和事件。遇到 panic、故障或超过 1 s 的卡顿时自动保存。rec save
内存与泄漏按类型划分的 RSS、malloc 在用与空闲持有的部分、Relax 自己的占用；按分配栈统计的程序堆，两次快照之间给出疑似泄漏。堆跟踪目前只支持 Linux x86-64 和 macOS arm64。memory、heap start、heap snap a、heap diff a now

只有你改过的函数会被重新检查、重新编译，然后热替换进正在运行的程序，状态全都保留。

构建它，跑一个包。

git clone https://github.com/makepad/relax
cargo build --release --manifest-path relax/Cargo.toml -p relax-runner --bin relax

cargo new hello
cd hello
../relax/target/release/relax run --quiet hello    # 在 JIT 下运行 main
../relax/target/release/relax test hello           # 运行它的 #[test] 函数
../relax/target/release/relax check hello          # 只做类型检查和借用检查

在包的目录里运行 relax，参数给包名；别移动 relax 的检出目录，std 从那里读取。在一台 16 核 x86-64 Linux 机器上构建用了 53 s；hello 随后 0.24 s 启动，之后不到 0.1 s。已在 Linux x86-64 和 macOS arm64 上测试。

没有依赖的包不需要联网；crates.io 依赖取自 ~/.cargo，或下载后按索引的 SHA-256 校验。更多见 README。

makepad run 里的 Relax。

Relax 出自 Makepad 项目。makepad run 及其工具在 Makepad 的仓库里，不在本仓库；本节介绍 Makepad 如何使用 Relax。

makepad 就是 Relax 的运行器加上 Makepad 的宿主。除 makepad run 外，下列命令都发给 makepad inspect <app>。

无需原生构建窗口立即打开并显示构建进度；应用的第一个窗口随后接管它。makepad run <package>
保存即补丁修改被热补丁进正在运行的应用，状态和窗口都保留。
原地重启无法热补丁的修改（类型布局、导入、trait 或 impl 头、宏）会在标题栏的 JIT 环上显示“Update ready”。点一下，应用就在同一进程、同一窗口里重启，带着它的状态（AppMain::restart_state）和窗口位置；有未保存的工作时可以推迟（AppMain::can_restart）。session relaunch
错误显示在窗口里编译错误和被借用检查器拒绝的修改显示在应用上方，带文件和行号。应用崩溃后窗口仍在，源码一改就提供 Restart。session view open
修好 panic 再重试panic 会暂停应用，JIT 环显示“Paused on a panic”；点一下就看到消息和位置。在 UI 线程上，改好代码、保存，retry 就用新代码重新运行那个事件。panics、locals panic=P1、resume P1 retry
看清代码每个函数的各个代码版本、O3 优化说明、与 rustc 并排的机器码，以及飞行记录器。versions <fn>、remarks <fn>、asm <fn> vs=rustc、rec save
驱动 UI应用的远程控制与 Relax 共用 inspect 套接字（仅限本用户，不经网络）。ui find q=<text>、ui act node=<id> press、grab

在 Makepad 智能体通道一天的数据里，修改到达机器后 3.6 s（中位数）就被热补丁进去；JIT 或缓存还冷时 p90 为 86 s。

LLVM 仍然领先的地方。

在稳定状态下，LLVM 生成的代码仍然更快。热 JIT 对比同一份源码、同样输入的原生构建，取实际耗时之比（越低越好，1.00× = LLVM）。

3D 打印切片器：零件首次切片，4 线程x86-64 (Zen 4)1.14×（周期数 1.15 倍，指令数 1.26 倍）测于 2026-11-11
同上，8 线程x86-64 (Zen 4)1.17×测于 2026-11-11
同上，4 线程AArch64 (Apple M4)1.24×（测于本周的 x86 优化移植过来之前）测于 2026-11-09
CAD B-rep 建模一轮x86-64 (Zen 4)1.26×测于 2026-11-10
脚本虚拟机的解释器循环x86-64 (Zen 4)1.19×测于 2026-11-11
密集数值内核（Cholesky 分解）x86-64 (Zen 4)2.29×（LLVM 用 AVX-512 把它向量化了，Relax 目前还不做循环向量化）测于 2026-11-10
任意负载对比普通 --release（可移植 CPU 基线）尚未测量

以上是我们最常剖析的负载。本周一次覆盖 18 个负载的更广泛测试结果更慢；我们正在查明原因。

哪个 --release？ 对比的是带 -C target-cpu=native 的 --release。大多数 Rust 程序用面向可移植 CPU 的普通 --release 发布，而 Relax 针对它所运行的 CPU 编译，所以那时差距会缩小。尚未测量。

切片器的差距在三天里从 1.26 倍缩小到 1.14 倍。其余差距从哪来：见 README。

一个函数的一生。

  • 解释器：代码从这里起步。
  • O1：机器码，已发布。
  • O3：变热后在后台重新编译；更快的代码，热替换上线。

换成 rustc，同样的改动意味着：重新构建 crate、重新链接、重启。
